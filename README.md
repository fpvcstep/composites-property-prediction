# Прогнозирование свойств композиционных материалов

После объединения двух исходных таблиц Excel получено 1023 строки и 13 колонок. Каждая строка содержит один предоставленный пример, а в колонках записаны характеристики материала и известные конечные свойства.

Задание требует оценить два конечных свойства:

1. **Модуль упругости при растяжении** – показывает жёсткость материала.
2. **Прочность при растяжении** – показывает, какую нагрузку на единицу площади материал выдерживает до разрушения.

В исходной таблице значения этих свойств известны. В работе из входов каждой прямой модели исключили обе колонки с конечными свойствами, поэтому из 13 колонок осталось 11 входных характеристик. Это решение принято потому, что для нового материала оба свойства могут быть неизвестны. При обучении модель видит 11 характеристик и правильное значение результата. После обучения пользователь вводит 11 значений, а приложение выдаёт две оценки – модуль и прочность.

Связующее, или матрица, соединяет компоненты материала. Наполнитель влияет на его свойства. Соотношение матрица–наполнитель также находится в исходной таблице.

Работа включает две группы задач. В основных задачах по 11 входным характеристикам прогнозируются модуль упругости и прочность; для каждого свойства сравниваются пять подходов: прогноз среднего, гребневая регрессия, случайный лес, градиентный бустинг и метод опорных векторов. Две выбранные модели включены в приложение.

Нейронная сеть тоже является методом машинного обучения, но здесь она выполняет отдельное обязательное поручение. Целью служит колонка «Соотношение матрица–наполнитель», а на вход подаются остальные 12 колонок, включая уже известные модуль упругости и прочность. Сеть сравнивается с прогнозом среднего, уступает ему и не включается в приложение.

Для обучения и проверки 1023 строки разделены на обучающую выборку из 716 строк и тестовую из 307 строк. Модели подбирались только по обучающей выборке, а тестовая использовалась один раз для итоговой проверки.

## Основные результаты

Ошибки ниже получены на тестовой выборке из 307 строк, которая не использовалась при выборе моделей. RMSE сильнее реагирует на крупные ошибки, MAE показывает средний размер ошибки без учёта знака, а R² сравнивает модель с прогнозом среднего и не является процентом точности.

| Задача | Модель | RMSE | MAE | R² | Вывод |
|---|---|---:|---:|---:|---|
| Модуль упругости при растяжении | прогноз среднего | 3,178 ГПа | 2,556 ГПа | −0,016 | Испытанные сложные модели не улучшили базовый прогноз |
| Прочность при растяжении | градиентный бустинг | 471,410 МПа | 380,152 МПа | 0,008 | Улучшение RMSE мало; практическая точность не подтверждена |
| Соотношение матрица–наполнитель | MLP, обязательный эксперимент | 0,944 | 0,777 | −0,040 | Нейросеть хуже прогноза среднего и не выбрана для приложения |

Для прочности RMSE градиентного бустинга немного ниже, чем у прогноза среднего (473,288 МПа), но MAE хуже: 380,152 против 378,984 МПа. Модель была выбрана заранее по средней RMSE перекрёстной проверки, а не по тестовой выборке.

## Последовательность исследования

1. **Проверить и объединить исходные таблицы.** Два файла Excel проверяются и соединяются по общему исходному индексу. Результат — 1023 строки и 13 содержательных столбцов.
2. **Заранее отделить итоговую проверку.** Из 1023 строк 716 используются для разработки, а 307 откладываются до конца и не влияют на анализ, подготовку или выбор модели.
3. **Изучить только 716 строк.** На них проверяются пропуски, распределения, разброс, необычные значения и простые связи между столбцами. Тестовые 307 строк в разведочном анализе не используются.
4. **Подготовить характеристики.** Для методов, чувствительных к числовому масштабу, значения приводятся к сопоставимому виду. Необычные значения лишь помечаются: вариант со всеми строками сравнивается с экспериментальным вариантом фильтрации.
5. **Обучить и сравнить модели внутри 716 строк.** Для модуля и прочности сравниваются пять подходов при десятикратной перекрёстной проверке. Для отдельной задачи соотношения сравниваются прогноз среднего и нейронная сеть. Выбор делается до просмотра тестовых результатов.
6. **Один раз проверить зафиксированные решения на 307 строках.** Эта оценка показывает качество при данном разделении таблицы; после неё модели не перенастраиваются.
7. **Использовать две прямые модели в приложении.** Пользователь вводит 11 характеристик и получает прогнозы модуля и прочности. Нейронная сеть для отдельной задачи соотношения в приложение не входит.
8. **Сохранить воспроизводимый результат в репозитории.** Код, данные, опубликованные модели, отчёты и команды запуска хранятся вместе, чтобы порядок расчётов можно было проверить.

## Полное воспроизведение в Docker

Требуются Docker Desktop и режим Linux containers. Команды выполняются из корня проекта. Переменная `PYTHONDONTWRITEBYTECODE=1` и отключённый pytest cache не создают служебные кэши в каталоге проекта. Контейнер собирается по Dockerfile; изменяемый тег базового образа и незакреплённая версия pip ограничивают побитовую воспроизводимость среды при будущей сборке.

```powershell
docker build -t composites-thesis:local .

docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "${PWD}:/workspace" -w /workspace composites-thesis:local python -m pytest -q -p no:cacheprovider
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "${PWD}:/workspace" -w /workspace composites-thesis:local python scripts/audit_data.py
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "${PWD}:/workspace" -w /workspace composites-thesis:local python scripts/prepare_data.py
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "${PWD}:/workspace" -w /workspace composites-thesis:local python scripts/run_eda.py
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "${PWD}:/workspace" -w /workspace composites-thesis:local python scripts/train_models.py
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "${PWD}:/workspace" -w /workspace composites-thesis:local python scripts/evaluate_models.py
```

`evaluate_models.py` выполняют после выбора по обучающей части: он один раз оценивает зафиксированные артефакты на отложенной выборке и формирует `reports/evaluation`, `figures/evaluation` и `models/model_manifest.json`.

Повторный `train_models.py` выполняет полный поиск гиперпараметров на обучающей части и итоговое обучение выбранных конфигураций; это может занимать несколько минут. Для изучения используйте опубликованные результаты и notebook с выключенным флагом `RETRAIN_ALL_MODELS`.

## Запуск без установки проекта в его каталог

Docker — рекомендуемый путь. Если нужен CPython 3.12, виртуальное окружение создаётся рядом с проектом, а импорт исходников задаётся через `PYTHONPATH`. Это не создаёт `.venv`, `egg-info` или bytecode внутри итогового каталога.

```powershell
$project = (Get-Location).Path
$venv = Join-Path (Split-Path -Parent $project) '.venv-composites'
py -3.12 -m venv $venv
& "$venv\Scripts\python.exe" -m pip install --upgrade pip
& "$venv\Scripts\python.exe" -m pip install -r "$project\requirements.lock.txt"
$env:PYTHONPATH = "$project\src"
$env:PYTHONDONTWRITEBYTECODE = '1'
& "$venv\Scripts\python.exe" -m pytest -q -p no:cacheprovider "$project\tests"
```

## Notebook

`notebooks/research.ipynb` читает опубликованные audit/EDA/modeling/evaluation-артефакты и поясняет каждый график. По умолчанию `RETRAIN_ALL_MODELS=False`, поэтому полный запуск не повторяет GridSearch и обучение моделей.

Для интерактивного запуска нужна вся папка проекта, а не отдельная копия `research.ipynb`:

1. Откройте JupyterLab из корня `composites-property-prediction` или из каталога `notebooks` внутри него.
2. Выберите ядро CPython 3.12, в котором установлены версии из `requirements.lock.txt`.
3. Выполните **Restart Kernel and Run All Cells**. Кнопка Play запускает только выбранную ячейку и не выполняет подготовку выше неё.
4. Убедитесь, что в начале выведено `RETRAIN_ALL_MODELS=False`; notebook должен читать готовые артефакты.

Если JupyterLab уже запущен из другого окружения, внешнее окружение проекта можно зарегистрировать как отдельное ядро после установки `requirements.lock.txt`:

```powershell
& "$venv\Scripts\python.exe" -m ipykernel install --user --name composites-thesis --display-name "CPython 3.12 (composites thesis)"
```

Выполнить notebook в контейнере и сохранить outputs можно без дополнительного служебного скрипта:

```powershell
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -e MPLBACKEND=Agg -v "${PWD}:/workspace" -w /workspace composites-thesis:local python -c "from pathlib import Path; import nbformat; from nbclient import NotebookClient; p=Path('notebooks/research.ipynb'); n=nbformat.read(p,as_version=4); NotebookClient(n,timeout=600,kernel_name='python3',resources={'metadata':{'path':'/workspace'}}).execute(); nbformat.write(n,p)"
```

## Streamlit-приложение

Приложение запускается из read-only bind mount:

```powershell
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -p 127.0.0.1:8501:8501 -v "${PWD}:/workspace:ro" -w /workspace composites-thesis:local streamlit run app/streamlit_app.py --server.address=0.0.0.0 --browser.gatherUsageStats=false
```

Откройте `http://localhost:8501`. Значения формы по умолчанию — медианы обучающей выборки, а не измеренный образец. Для содержательного прогноза введите фактические 11 характеристик. Выход за минимумы и максимумы обучающей выборки сопровождается предупреждением об экстраполяции. Приложение выдаёт модуль в ГПа и прочность в МПа; метрики тестовой выборки описывают модель в целом и не являются неопределённостью отдельного прогноза.

## Ограничения

Неизвестны происхождение наблюдений, партии и серии, типы матрицы и наполнителя, а также смысл части единиц. Случайное разбиение оценивает качество на отложенных строках той же таблицы при данном разбиении; перенос на новые классы материалов не проверен. Прогнозы не заменяют лабораторные испытания.
